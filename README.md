# 债券说明文字中的用途承诺与付款复核

募集款受托业务的虚构原条款、申请、凭据和外部付款台账。材料中的人、机构及经营记录是合成的。

每份资料为 UTF-8 JSON 数组。id 在同一份资料内唯一，原始文字按收到的形式保留。

- `data/terms.json`。虚构受托条款文本。rank 越小效力越优先。from 为生效日，source 描述签发来源，text 是原条款。金额采用整数元。
- `data/claims.json`。申请人提交的费用及凭据。部分申请允许按份额独立审议。invoice_id 去重到原凭据，份额不等同于最终用途判定。
- `data/ledger.json`。上期外部签付台账以及银行回单。business_ref 可链接到收到的申请，amount 仅是外部实付或原签金额，文本附有原签解释。
- `data/proofs.json`。送来的合同和凭据补件。invoice_id 连接支付原件。received 为受托人实际收到的时间，contract_scope 保留出具方对凭据的描述。

使用 Python 3.11 标准库，无需安装软件包或连接外部服务。

以下命令分别读取一份原始资料、检查资料中的字段与关联。

```sh
python3 -m json.tool data/terms.json
python3 -m unittest discover -s tests -v
```

## 受托人付款审核工作台（trustee_workbench）

在签批前把"说明书的话"和"实际要付的钱"对应起来：每笔可付部分都带依据链，
每条无法批准的原因都留痕。运行完整虚构演示：

```sh
python3 -m trustee_workbench
```

- `trustee_workbench/model.py`。条款原文（Term）只读保存；受托人解释登记为规则
  （Rule：封顶数/目标数/预留额/自筹比例/排除项/解除），按单笔、项目、最终受益人、
  一组用途分层，每条规则记录所依据的条款或补件 id。
- `trustee_workbench/workbench.py`。引擎：对象与受益人凭原文裁定判定（不按名称相近
  猜测）；凭据份额分别核算、同一笔唯一归属；双披露口径只计一次；缺身份、费用构成或
  适用时点的部分受阻待补证，独立成立部分按付款请求的拆分许可处理；可动用余额同时
  受预留额、已签未付承诺和已付资金约束；多种合法归属时检查是否锁死已签项目的后续
  额度，签批人可查到可行归属及无法批准的原因。
- 补充说明生效（apply_note）：仍能履行的承诺保留，可能超限的待付部分先冻结，
  已付部分留原账和当时依据并发复核/追补指示；补回资金回到实际被占用的额度，
  确已满足的冻结随之解除；语义歧义由受托人裁定（rule_on_dispute）并留依据。
- `trustee_workbench/scenario.py`。按时间线跑通全部虚构资料：混合句发票拆分、
  相近名目判定、T4 收紧、C5 双归属均不可行、P3 补证与 L4 回补、T5 邮件裁定、
  C4 口径改列不另付款，期末输出余额与额度占用，并沿 C3/C5 打印交接追踪
  （trace：同一笔钱的原文解释→核准→实付→复核→回补）。
- `tests/test_workbench.py`。引擎机制的单元测试（虚构小场景）及全套资料的时间线
  回归测试。
